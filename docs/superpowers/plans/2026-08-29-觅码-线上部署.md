# 觅码 · 线上部署 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按《2026-08-29-觅码-线上部署-design.md》落地方案 A：修复 feed 客户端、产出 systemd/Nginx 模板与 GitHub Actions 工作流、编写服务器一次性初始化 runbook，实现 push 到 `feat/frontend-ui` 自动部署。

**Architecture:** 前端在 GitHub Actions 构建（`VITE_USE_MOCK=false`）后 rsync 到服务器 `/var/www/meecode`；后端 FastAPI 以 systemd 常驻 `127.0.0.1:8100`；Nginx 443 托管静态文件并把 `/explain-api/` 重写转发到 `/api/`；部署链 `&&` 串联失败即中止。

**Tech Stack:** GitHub Actions（ubuntu-latest, Node 20）、rsync over SSH、FastAPI + uvicorn + systemd、Nginx + certbot（Let's Encrypt）。

## Global Constraints

- 部署分支为 `feat/frontend-ui`（GitHub 当前默认分支），workflow `on.push.branches` 必须用这个名字。
- 后端监听 `127.0.0.1:8100`，单 worker；Nginx 重写规则必须是 `location /explain-api/ { proxy_pass http://127.0.0.1:8100/api/; }`（尾斜杠）。
- 生产前端构建环境变量 `VITE_USE_MOCK=false`；信息流恒走 mock，仅解读功能走真实后端。
- 密钥只存在于服务器 `/opt/meecode/backend/.env` 与 GitHub Secrets；`.env` 已被 `.gitignore` 忽略，任何步骤不得提交它。
- 流式接口依赖：Nginx 必须 `proxy_buffering off`、`proxy_read_timeout 300s`。
- **本机工作区存在无关未提交改动**：每个提交步骤只 `git add` 本任务明确列出的文件，禁止 `git add -A`/`git add .`。
- 服务器目录约定：仓库克隆在 `/opt/meecode`，静态产物在 `/var/www/meecode`，运行用户 `deploy`。
- 模板文件中的 `<你的域名>` 是部署参数（runbook 第 5/7 步替换），不是待办占位。

### Task 3: Nginx 站点配置模板

**Files:**
- Create: `deploy/nginx-meecode.conf`

**Interfaces:**
- Consumes: 设计文档 §5；静态目录 `/var/www/meecode`；后端 `127.0.0.1:8100`。
- Produces: runbook（Task 5）第 5/7 步使用的最终配置；`/explain-api/` 前缀被前端 `explain/api/client.ts` 的请求路径依赖，重写规则必须与 vite 开发代理等价。

- [ ] **Step 1: 写文件**

新建 `deploy/nginx-meecode.conf`：

```nginx
# 觅码线上站点配置（最终形态）
# 使用方式见 docs/deploy-runbook.md 第 5/7 步：先装 80 端口最小配置签证书，
# 再替换为本文件并 reload。部署前把 <你的域名> 全部替换为实际域名。
server {
    listen 80;
    server_name <你的域名>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name <你的域名>;

    ssl_certificate     /etc/letsencrypt/live/<你的域名>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<你的域名>/privkey.pem;

    root /var/www/meecode;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /explain-api/ {
        proxy_pass http://127.0.0.1:8100/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

要点核对：尾斜杠使 `/explain-api/health` → `/api/health`；`proxy_buffering off` 保 NDJSON 流式；`try_files` 兜底 react-router 深链接；`/api` 无 location，信息流 mock 不发网络请求。

### Task 4: GitHub Actions 部署工作流

**Files:**
- Create: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: GitHub Secrets `SSH_HOST`（`deploy@服务器IP`）、`SSH_PRIVATE_KEY`（ed25519 私钥，runbook 第 4 步生成）、`DEPLOY_DOMAIN`（runbook 第 8 步配置）；服务器 `/opt/meecode`、`.venv` 布局（Task 2/5）。
- Produces: push 到 `feat/frontend-ui` 的自动部署管道；`concurrency` 组名 `deploy-prod`。

- [ ] **Step 1: 写文件**

新建 `.github/workflows/deploy.yml`：

```yaml
name: deploy

on:
  push:
    branches: [feat/frontend-ui]
    paths:
      - 'frontend/**'
      - 'backend/**'
      - '.github/workflows/deploy.yml'

concurrency:
  group: deploy-prod
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: frontend/package-lock.json

      - name: Build frontend
        working-directory: frontend
        env:
          VITE_USE_MOCK: 'false'
        run: npm ci && npm run build

      - name: Setup SSH key
        env:
          SSH_HOST: ${{ secrets.SSH_HOST }}
          SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
        run: |
          mkdir -p ~/.ssh
          printf '%s\n' "$SSH_PRIVATE_KEY" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          ssh-keyscan -H "${SSH_HOST##*@}" >> ~/.ssh/known_hosts

      - name: Upload frontend dist
        env:
          SSH_HOST: ${{ secrets.SSH_HOST }}
        run: |
          rsync -az --delete -e "ssh -i ~/.ssh/deploy_key" frontend/dist/ "$SSH_HOST:/var/www/meecode/"

      - name: Deploy backend
        env:
          SSH_HOST: ${{ secrets.SSH_HOST }}
        run: |
          ssh -i ~/.ssh/deploy_key "$SSH_HOST" '
            set -e
            cd /opt/meecode
            git pull --ff-only
            backend/.venv/bin/pip install -r backend/requirements.txt
            sudo systemctl restart meecode-backend
          '

      - name: Health check
        env:
          DEPLOY_DOMAIN: ${{ secrets.DEPLOY_DOMAIN }}
        run: |
          for i in 1 2 3 4 5; do
            if curl -fsS "https://${DEPLOY_DOMAIN}/explain-api/health"; then exit 0; fi
            sleep 5
          done
          exit 1
```
