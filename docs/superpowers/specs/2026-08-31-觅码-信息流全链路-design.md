# 觅码 · 信息流全链路（合并至可部署）设计文档

日期：2026-08-31 · 状态：已确认 · 需求来源：会话评审（基于 `2026-08-24-觅码-收录与浏览-design.md` 与 worktree 实现）

## 1. 背景与目标

信息流后端已在 git worktree 分支 `worktree-meecode-sdd` 上按已确认的收录与浏览设计文档完整实现（FastAPI + SQLite/WAL + FTS5、投稿/采集/LLM 筛选、排名与预留位、GitHub OAuth、爬取与日报任务、141 个测试全绿）。但该分支与主开发分支 `feat/frontend-ui`（含仓库解读后端）从 `bf7929a` 分叉后各自演进：

- worktree 分支**替换**了 `backend/app`（不含解读后端），前端无 `explain` 模块；
- 主分支前端信息流 `client.ts` 恒走 mock，Nginx 无 `/api` location；
- 两侧 DTO 契约有分歧（响应包裹、时间戳格式、卡片字段、搜索排序、分类枚举）；
- 代码评审发现 5 项上生产前必修问题（见 §3）。

**目标**：把 worktree 实现合并进主开发分支，修复全部评审问题，完成前端接线与部署集成，达到全链路可部署。

**非目标（YAGNI）**：推荐算法（属子项目 3）、变现、Postgres/Redis、多 worker、GitHub token 持久化、管理后台。

## 2. 架构：合并为单一 FastAPI 应用

信息流后端整体平移为 `backend/app/feed/` 子包，与解读后端共存于同一应用，**端口保持 8100**（Nginx `/explain-api/` 上游、systemd 单元、健康检查均不变）：

```
backend/app/
  main.py          # 合并入口：挂载解读路由 + feed.routes.* 于 /api
  config.py        # 合并配置：LLM_* / TAVILY / GITHUB_* / SESSION_SECRET / DB_PATH / 排序与爬取参数
  schemas.py       # 解读域 schemas（原名不动）
  gh.py, agent/    # 解读域原样保留
  feed/            # worktree 的 app/* 整体平移，相对导入上提一级
    db.py, deps.py, auth.py, github.py, cards.py, llm.py,
    ranking.py, screening.py, mock.py, schemas.py, routes/, jobs/
```

决策理由：

- `config.py` / `llm.py` / `main.py` / `mock.py` 两侧重名，平铺合并会互相覆盖；子包隔离使迁移以「复制 + 调 import」为主，不做 git merge（历史已分叉）。
- 单进程即可：解读的内存会话本就强制单 worker，SQLite 单进程写入正合适。
- 共享 `config.py` 于应用根，feed 包经 `..` 引用；feed 的 `llm.py`（精筛/AI 文案）职责独立，随包平移。
- `requirements.txt` 取并集（feed 未引入新依赖）。

## 3. 后端修复项（评审发现，全部纳入）

| # | 修复 | 位置 |
|---|------|------|
| 1 | 全局共享 SQLite 连接 → **每请求连接** + `busy_timeout=5000`；DB 初始化移至应用根 `main.py` 的 lifespan 启动时（fail-fast） | `feed/deps.py`、`main.py` |
| 2 | `toggle_interaction` 改条件写入（`ON CONFLICT` + rowcount 判断），消除读改写竞态导致的并发 500 | `feed/routes/me.py` |
| 3 | GitHub 重试分两级：交互路径（文件/树/元数据）等待 ≤2s、重试 1 次；批量路径（爬取）保持现状；改模块级共享 `httpx.Client` 连接池 | `feed/github.py` |
| 4 | OpenAI 客户端显式 `timeout=30, max_retries=1`（默认 600s 读超时会让 `/api/ai-draft` 最坏挂 20 分钟） | `feed/llm.py` |
| 5 | `GITHUB_MOCK=false` 且 `SESSION_SECRET` 为默认值时**拒绝启动**；非 mock 模式下 session/state cookie 加 `secure=True` | `feed/config.py`、`feed/routes/me.py` |
| 6 | `cover_url` 校验：仅 http(s)、长度上限（防存储型 XSS / 钓鱼） | `feed/schemas.py` |
| 7 | 爬取先按规则分启发式排序，仅对 **top-K（K = CRAWL_DAILY_QUOTA + 5，config 可调）** 做 LLM 精筛，再截断入库，封顶 LLM 花销 | `feed/jobs/crawl.py` |
| 8 | 爬取任务每轮补筛最多 10 个（config 可调）`screened=0` 仓库（兑现「质量待补齐」承诺） | `feed/jobs/crawl.py` |
| 9 | `list_user_repos` 翻页拉全（>100 仓库的作者可投稿） | `feed/github.py` |
| 10 | 零散小修：trigram 短查询（<3 字符）回退 `LIKE`；`Retry-After` 非 HTTP-date 解析守卫；OAuth token 交换对非 JSON 响应守卫；print→logging；smoke 脚本断言修正 | `feed/routes/feed.py`、`feed/github.py` 等 |

## 4. API 契约对齐（后端向既有前端类型看齐）

前端 `frontend/src/api/types.ts` 已声明「后端就绪后不改前端类型」，故由后端适配，目标为**精确匹配 `ApiClient` 接口**：

- `GET /api/feed` 返回 `{cards, has_more}`。卡片字段映射：`title` = full_name 仓库名段；`views` = `repo_view_count`；`likes` = interactions(kind=like) 计数（JOIN 查询，不改表结构）；`published_at` 转 ISO 字符串；`cover_url` 空串转 `null`；`favorites_count` 缺省（前端 UI 已兼容缺省不显数字）。
- `GET /api/search` 增加 `sort` 参数：`default` = FTS5 bm25 相关度、`newest` = published_at 降序、`stars` = stars 降序。
- **分类枚举以收录与浏览 spec 确认的后端 8 类为准**：`开发工具 / Web 应用 / AI 与机器学习 / 系统与底层 / 数据处理 / 游戏与图形 / 学习资源 / 其他`。前端 fixtures 的 `CATEGORIES` 同步更新（`系统底层`→`系统与底层`，去`效率脚本`，增`游戏与图形`/`学习资源`）。
- 新增 `GET /api/repos/{id}/related`：同分类、排除自身、按 score 取前 4（config 可调）—— mock 契约存在而 worktree 后端缺失。
- 补齐 mock 契约中 worktree 后端缺失的端点（`myLikes` 返回 id 列表等），plan 阶段以 `ApiClient` 逐方法对表核验。

## 5. 前端接线

- `frontend/src/api/client.ts`：按 `VITE_USE_MOCK` 分流 —— 缺省（true/缺省）走 mock 保留离线开发体验；`false` 走真实客户端 `fetch('/api/...')`，`credentials: 'include'`。`ApiClient` 类型不变，删除「恒走 mock」的临时逻辑。
- `frontend/src/api/fixtures.ts`：`CATEGORIES` 按后端 8 类更新（见 §4）。
- `frontend/vite.config.ts`：dev 代理新增 `/api` → `http://127.0.0.1:8100`。
- 登录走真实 GitHub OAuth：`LoginModal` 已按 `loginUrl()`（`/api/auth/github`）实现，无需改动。

## 6. 部署集成

- **Nginx**：新增 `location /api/ { proxy_pass http://127.0.0.1:8100; }`（无 rewrite，复用现有 buffering/timeout 配置）。
- **cron**（更新 `docs/deploy-runbook.md`）：`0 3 * * *` 爬取、`0 4 * * *` 曝光合规日报。
- **GitHub OAuth App**（手动运维步骤，写入 runbook）：callback `https://<domain>/api/auth/callback`；服务器 `.env` 新增 `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`SESSION_SECRET`（必填，无默认回退）、`GITHUB_TOKEN`（爬取配额 5000/h）。
- CI 工作流不变：已是 `VITE_USE_MOCK=false` 构建 + rsync + systemd 重启 + 健康检查。

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 解读域与精筛共用同一 LLM key/model，配额互相挤占 | 单机 MVP 可接受；`LLM_MOCK` 可独立验证两域；后续可拆分 key |
| SQLite 写入集中单进程，爬取批处理与在线写并发 | WAL 读写不互斥 + 每请求连接 + `busy_timeout`；爬取在低峰时段 |
| OAuth App 配置遗漏导致登录不可用 | runbook 前置检查清单 + `/api/health` 之外增加登录链路冒烟 |
| 合并 conftest 时 autouse fixture 冲突 | plan 阶段先跑平移后的全量测试再动手改 |
